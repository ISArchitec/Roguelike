# Конфигурация игры

`GlobalConfig` находится в `play_cycle/global_config.py`. `GlobalConfig.get_instance()` загружает единственный общий экземпляр из `configs/config.json`; путь определяется относительно Python-файла, независимо от текущей директории. Для отдельной конфигурации используется `GlobalConfig(path)`, без замены общего экземпляра.

Значения в поставляемом JSON — начальный пример для разработки, а не утверждённый баланс игры. Все перечисленные ниже поля, кроме `actual_saves`, обязательны.

- `actual_saves`: массив актуальных дат создания попыток в ISO 8601 с часовым поясом, например `2026-11-17T12:34:56.123456+00:00`. В памяти это множество `datetime`, нормализованное в UTC. Если поле отсутствует, реестр пуст.
- `map_size`: `[width, height]`, положительные целые размеры карты.
- `initial_hero_params`: объект с целочисленными `health`, `defence`, `attack`, `speed`.
- `monster_param_pool`, `boss_param_pool`: массивы таких объектов характеристик.
- `object_view`: отображение типа объекта в строку для вывода. Доступные типы: `hero`, `monster`, `boss_monster`, `certificate`, `id_card`.
- Стратегии: `GlobalConfig` регистрирует `simple` в коде. `get_boss_strategy(name)` возвращает фабрику `SimpleMonsterStrategy`; `get_boss_strategies()` — имена зарегистрированных стратегий.
- `boss_id_cards`: массив удостоверений. Каждое содержит `attack`, неотрицательный целочисленный `timeout`, `position: [x, y]` с неотрицательными целыми координатами и неотрицательный целочисленный `tick_since`. Позиция и счётчик относятся к шаблону; при размещении объекта координаты задаются через `set_position`. `tick_since` — тик последней атаки: следующая доступна при `Game.get_ticks() - tick_since >= timeout`. При начальном `tick_since: 0` первая атака доступна начиная с тика `timeout`. Привязка часов через `set_tick_getter` не сбрасывает этот счётчик.
- `certificates`, `initial_thing_pool`: массивы объектов характеристик для справок и одноразовых бонусов; отрицательные модификаторы допустимы.
- `initial_thing_count`: неотрицательное целое количество стартовых одноразовых предметов; в примере — 3. `Game` равновероятно выбирает каждый предмет из `initial_thing_pool` с повторениями и создаёт независимую копию. При положительном количестве пул не может быть пустым; при нуле создаётся пустой инвентарь.

Форматы `attack`:

```json
{"type": "circle", "radius": 1, "force": 5}
{"type": "straight", "length": 3, "direction": "UP", "force": 5}
{"type": "wave", "forces": [5, 3, 1]}
```

Каждая строка в примере — отдельный объект `attack`. Для направления допустимы `UP`, `DOWN`, `LEFT`, `RIGHT`. Радиус, длина и силы — неотрицательные целые числа.

Геттеры характеристик, пулов и предметов возвращают хранящиеся в конфигурации объекты. При создании стартового инвентаря `Game` копирует каждый выбранный предмет отдельно, поэтому его состояние не меняет шаблон или другие экземпляры. Размер карты возвращается кортежем, список имён стратегий — итератором.

Отсутствующий файл, некорректный JSON, обязательное поле или неизвестное имя приводят к исключению; значения по умолчанию вместо ошибочных данных не подставляются. В стандартном запуске `Console` связывает `CommonLevelGenerator` с `BossLevelGenerator`: после четырёх обычных уровней создаётся уровень босса. `Game` получает от генератора `(map, enemies, is_section_end)` и завершает игру после подбора награды пятой секции. Размер секции и число секций пока заданы в коде, а не в JSON.

Новая игра регистрирует дату попытки в `actual_saves`. `Game.get_save_date()` возвращает эту дату для сохранения; при загрузке её нужно передать в `Game.create_from(..., save_date=...)` как `datetime`. Если даты нет в реестре, загрузка отклоняется с `ValueError`. Все файлы сохранений одной попытки должны сохранять одну и ту же дату, а не время последней записи. Смерть героя удаляет эту дату и инвалидирует все сохранения попытки, не затрагивая другие игры. Реестр записывается в JSON через временный файл и атомарную замену; состояние игры отдельно записывается через `GameLoader.save_to_file()`.


## Сохранение состояния игры

`serializing.GameLoader` преобразует игру в `GameData` (`save_to`) и обратно (`load_from`); файловые методы `save_to_file` и `load_from_file` работают с JSON. Корневой объект содержит `snapshot` и `checksum`. Поле `snapshot.version` сейчас равно `1`; другая версия отклоняется. `checksum` — SHA-256 канонического JSON снимка (сортировка ключей, компактные разделители, UTF-8), проверяемый до восстановления объектов; это контроль целостности, а не защита от намеренной подмены.

В снимок входят `generator`, `section_passed`, `ticks`, `enemy_count`, `thing_got`, `is_section_end`, `reward_placed`, `save_date`, `actors` и `map`. Герой находится первым в `actors`; клетки карты ссылаются на участников через `actor_index`, а награды хранятся как объекты клетки. Позиция клетки определяется её индексом и шириной карты. Состояние генератора включает продвижение внутри секции. Хранятся характеристики, инвентари, выбранное удостоверение, `tick_since` и параметры атак. Точная схема и проверка типов находятся в `serializing/save_data.py`.

Очередь ввода и исполняемые callback-функции не сериализуются. При загрузке передаются новая `Queue[IEvent]` и подписчик; восстанавливаются ссылки героя и врагов на карту, callback учёта удалённых объектов и обработчики подбора наград, а удостоверения привязываются к `Game.get_ticks`.

`Console` сохраняет игру на границе тиков, перед следующим ходом героя: команда `save` в середине хода откладывается, а при выходе оставшиеся действия пропускаются и враги завершают свой ход. Снимок не содержит позиции внутри хода врагов или очереди ещё не выполненных команд. После загрузки начинается ход героя. Для старого формата обычного генератора без `boss` и `level_in_section` загрузчик восстанавливает генератор босса из конфигурации и устанавливает `level_in_section = 1`: текущий уровень считается первым в секции. Консоль сообщает о таком восстановлении прогресса.

Файл записывается во временный файл в том же каталоге, сбрасывается через `flush` и `fsync`, затем атомарно заменяется через `os.replace`. Каталог `saves` создаёт консоль; `GameLoader` ожидает существующий родительский каталог. После смерти героя запись запрещена, а все файлы с датой этой попытки становятся недействительными через реестр `actual_saves`.
