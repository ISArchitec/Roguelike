# Функциональные требования

## 1. Управление игрой (management-операции игрока)

| ID    | Требование                                                                                                                  | Приоритет |
|-------|-----------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-01 | Система должна позволять начать новую игру. При старте генерируется карта первого уровня и случайный набор предметов рюкзака | Высокий   |
| FR-02 | Система должна сохранять полное состояние игры в файл: позицию персонажа, характеристики, содержимое всех трёх инвентарей, состояние кулдаунов, текущий уровень и секцию | Высокий   |
| FR-03 | Система должна загружать сохранение с диска и восстанавливать полное состояние, идентичное моменту сохранения                      | Высокий   |
| FR-04 | При загрузке система должна явно индицировать игроку, если сейчас не его ход (например, ход врагов был прерван сохранением)         | Средний   |
| FR-05 | Система должна выполнять автосохранение при выходе из игры (закрытие окна, SIGTERM)                                        | Высокий   |
| FR-06 | Система должна инвалидировать все существующие сохранения после смерти персонажа; загрузка таких сохранений должна быть невозможна    | Высокий   |

---

## 2. Игровой процесс (gameplay-операции персонажа)

### 2.1. Перемещение и ближняя атака

| ID    | Требование                                                                                                                       | Приоритет |
|-------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-07 | Персонаж может переместиться в соседнюю по стороне клетку, если она проходима и свободна                        | Высокий   |
| FR-08 | При попытке перемещения в клетку с врагом должна производиться ближняя атака; урон вычисляется по формуле, учитывающей атаку персонажа и защиту врага | Высокий   |
| FR-09 | Если здоровье врага достигает нуля — враг погибает и удаляется с карты                                                                  | Высокий   |
| FR-10 | При перемещении в непроходимую клетку (стена) должна быть дана понятная обратная связь                                        | Средний   |

### 2.2. Специальная атака

| ID    | Требование                                                                                                                       | Приоритет |
|-------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-11 | Персонаж может применить специальную атаку, тип которой определяется активным удостоверением                                | Высокий   |
| FR-12 | После применения специальной атаки должен быть установлен кулдаун в соответствии с конфигурацией удостоверения                   | Высокий   |
| FR-13 | Кулдаун специальной атаки уменьшается на 1 в конце каждого хода персонажа                                                         | Высокий   |
| FR-14 | У обычных врагов специальных атак нет; у боссов может быть несколько специальных атак с независимыми кулдаунами                    | Средний   |

### 2.3. Использование предметов

| ID    | Требование                                                                                                                       | Приоритет |
|-------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-15 | Персонаж может использовать предмет из рюкзака: применить модификатор характеристики или восстановить здоровье                   | Высокий   |
| FR-16 | После использования предмет должен быть удалён из инвентаря рюкзака                                                               | Высокий   |
| FR-17 | Временные модификаторы от предметов рюкзака действуют в течение одного уровня и сбрасываются при переходе на следующий уровень    | Высокий   |

### 2.4. Экономика действий и ходы

| ID    | Требование                                                                                                                       | Приоритет |
|-------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-18 | Ход персонажа завершается, когда все действия израсходованы или игрок завершил ход явно                                              | Высокий   |
| FR-19 | После хода персонажа наступает ход врагов; во время хода врагов действия персонажа недоступны                                     | Высокий   |

---

## 3. Уровни, секции и переходы

| ID    | Требование                                                                                                                       | Приоритет |
|-------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-20 | Уровень считается пройденным, когда все враги на нём побеждены                                                                   | Высокий   |
| FR-21 | При завершении обычного уровня персонаж получает случайную справку; после этого генерируется следующий уровень                   | Высокий   |
| FR-22 | При завершении уровня с боссом (не последнего) игроку предоставляется выбор из двух удостоверений; после выбора происходит переход на новый уровень | Высокий   |
| FR-23 | При завершении финального уровня показывается концовка — получение паспорта                                                      | Высокий   |
| FR-24 | При входе на новый уровень игроку даётся возможность сменить удостоверение; после выбора смена блокируется до конца уровня        | Высокий   |
---

## 4. Инвентари

| ID    | Требование                                                                                                                       | Приоритет |
|-------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| FR-25 | Система должна предоставлять просмотр справок                             | Средний   |
| FR-26 | Система должна предоставлять просмотр удостоверений                                                                               | Средний   |
| FR-27 | Система должна блокировать смену удостоверения в середине уровня; смена доступна только при входе на новый уровень                | Высокий   |
| FR-28 | Система должна отображать предметы рюкзака и позволять их использование в свой ход                                                | Высокий   |
| FR-29 | При старте новой игры персонажу выдаётся фиксированное число восстановлений здоровья и случайный набор модификаторов характеристик | Высокий   |
| FR-30 | В ходе игры рюкзак не пополняется                                                                                                | Высокий   |

# Нефункциональные требования

## 1. Надёжность и целостность данных

| ID     | Требование                                                                                                                       | Приоритет |
|--------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| NFR-01 | Сохранение должно быть атомарным: при прерывании записи старый файл не должен повреждаться (запись через временный файл + rename)  | Высокий   |
| NFR-02 | После инвалидации (смерть персонажа) сохранения не могут быть загружены, даже если файлы физически остались на диске              | Высокий   |
| NFR-03 | Автосохранение при выходе должно срабатывать при любом завершении сеанса (закрытие окна, SIGTERM)                                      | Средний   |
| NFR-04 | При аварийном завершении игры последнее успешное сохранение должно оставаться валидным                          | Средний   |
| NFR-05 | Игра должна корректно восстанавливаться после загрузки состояния, прерванного в середине хода врагов                               | Высокий   |

---

## 2. Удобство использования

| ID     | Требование                                                                                    | Приоритет |
|--------|-----------------------------------------------------------------------------------------------|-----------|
| NFR-06 | Интерфейс должен явно показывать, чей сейчас ход (игрока или врагов)                          | Высокий   |
| NFR-07 | Все запрещённые действия (недоступная клетка, кулдаун, смена удостоверения) должны сопровождаться понятной обратной связью | Высокий   |
| NFR-08 | Отображение четырёх характеристик персонажа и кулдаунов должно быть постоянно доступно        | Высокий   |
| NFR-09 | Просмотр всех трёх инвентарей должен быть доступен без прерывания игрового процесса           | Средний   |
| NFR-10 | Все игровые действия должны быть выполнимы без использования мыши (управление с клавиатуры)   | Средний   |
| NFR-11 | Обучение (туториал) или подсказки должны объяснять базовые механики при первом запуске        | Средний   |

---

| NFR-14 | Игра должна корректно работать с различными разрешениями экрана       | Средний   |

## 4. Расширяемость и сопровождаемость

| ID     | Требование                                                                                                                       | Приоритет |
|--------|----------------------------------------------------------------------------------------------------------------------------------|-----------|
| NFR-15 | Секции, типы врагов, справки, удостоверения и предметы рюкзака должны быть описаны в данных (конфигурация), а не захардкожены     | Высокий   |
| NFR-16 | Формулы урона и модификаторы характеристик должны быть вынесены в конфигурируемые параметры                                       | Высокий   |
| NFR-17 | Добавление новой секции не должно требовать изменения кода игрового цикла                                                        | Высокий   |
| NFR-18 | Код должен быть покрыт модульными тестами ключевых механик (бой, инвентари, сохранения) не менее чем на 80%                       | Средний   |
| NFR-19 | Игровая логика должна быть отделена от представления (UI) для возможности тестирования без графики                                | Высокий   |
